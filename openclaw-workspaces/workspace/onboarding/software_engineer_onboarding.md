## 📅 Training Schedule

### Week 1: Orientation & Observation
**Goal:** Understand our systems, standards, and workflows

| Day | Focus | Tasks |
|-----|-------|-------|
| 1 | Welcome & Setup | Read this doc, explore repos, understand architecture |
| 2 | Codebase Tour | Review CRM and kanban code, understand patterns |
| 3 | Shadow William | Observe how tasks are handled, ask questions |
| 4 | Documentation | Document any gaps you find (great first contribution!) |
| 5 | First Mini-Task | Small bug fix or improvement (William assigns) |

**Check-ins:** Daily with William

### Week 2: Guided Development
**Goal:** Complete small tasks with close supervision

- Assigned 2-3 small, well-defined tasks
- William reviews all code before deployment
- Focus on learning our standards and patterns
- Ask questions freely — no such thing as a dumb question

**Check-ins:** 2x daily (morning priorities, end-of-day review)

### Week 3: Increasing Ownership
**Goal:** Take on larger tasks with less hand-holding

- Own a feature or project end-to-end
- William available for questions but not reviewing every line
- Start proposing improvements, not just completing assignments
- Debugging and troubleshooting independently

**Check-ins:** Daily standup

### Week 4+: Full Autonomy
**Goal:** Operate independently on most tasks

- Own projects from concept to deployment
- Proactively identify and fix issues
- Mentor future team members (when we grow)
- Weekly 1:1 with William for bigger picture alignment

**Check-ins:** Weekly 1:1

## 📋 Coding Standards

### General Principles
1. **Readability > Cleverness** — Code is read more than written
2. **Comments explain "why"** — Code shows "what"
3. **Small commits** — Atomic, focused changes
4. **Test before deploy** — Always verify locally first

### JavaScript/Node.js Conventions
- Use `const` by default, `let` when needed
- Async/await over callbacks
- Meaningful variable names
- Error handling on all async operations

### File Organization
```
/workspace
├── /crm          # CRM application
├── /kanban       # Kanban board
├── /books        # Learning resources
├── /memory       # Daily logs
├── /scripts      # Utility scripts
└── /showings     # Client prep docs
```

### Git Workflow
1. Write clear commit messages
2. Push to `master` (we're small, keep it simple)
3. Verify deployment succeeded on Render
