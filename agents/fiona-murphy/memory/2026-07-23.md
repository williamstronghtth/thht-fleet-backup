## Session — 08:45 ET (Yoast "0 words" root cause found: missing Gutenberg block markup)
- **What was done:** Chris pasted a Yoast Premium analysis showing 14 problems including "The text contains 0 words" and "No focus keyphrase was set." Verified against the database: post 49444 actually had 609 words, keyphrase "Hillsborough County real estate", a 147 char meta description, and featured image 49446 all correctly saved. So the copy was fine and the analyzer was blind.
- **Root cause:** posts published via the WP REST API are stored as plain classic HTML with zero `<!-- wp:paragraph -->` block delimiters. The block editor loads that as an unparsed classic blob and Yoast's editor-side analyzer reads it as 0 words, which cascades into every keyphrase check failing simultaneously. This, not the copy, is why the analysis looked catastrophic.
- **Fix applied:** wrote a converter that splits classic HTML on blank lines and wraps each chunk in the right block comment (paragraph / heading with level / list / quote / html). Ran it on post 49444, now 13 proper blocks, content and word count unchanged at 609.
- **Key decisions:** Made block formatting mandatory check #11 in yoast-green-checklist.md rather than a one-off fix, since every future API-published post would hit the same wall. Included the verification one-liner (grep -c "<!-- wp:" must be > 0).
